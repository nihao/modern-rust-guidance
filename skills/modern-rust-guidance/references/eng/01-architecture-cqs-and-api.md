# Eng 01 — 工程范式分工（DDD/DOD）、CQS、模块切片与内部 API

本分册定义软件工程范式正交分工（轻量 DDD、实用 DOD 与 OOP 取舍）、命令查询分离（CQS）、纯核心与副作用外壳隔离、工程角色命名及内部工作区 API 克制准则。

## 1. 职责分层、CQS 与工程范式正交分工

### 1.1 用例级 CQS 与强一致边界
- **写命令（Command）**：改变系统状态，驱动纯规则裁决并在单一事务内原子写入正式状态、伴生审计与幂等收据，返回提交结果或收据。
- **只读查询（Query）**：直接读取已提交数据并扁平投影（可复用纯派生函数），不产生写副作用、不加排他行锁、不驱动写状态机，也不按当前可变配置隐式重算历史已定案快照。查询视图不得回流充当受信写入凭据。
- **跨库交接边界**：强一致状态变更在所属单库事务内原子闭环；跨独立数据库边界通过显式协议与不可变引用交接，禁止依赖跨库分布式事务或隐式后台修补掩盖不一致。

### 1.2 函数式纯核心与命令式外壳（FCIS）
统一采用 **“类型化输入事实 ＋ 纯决策／纯变换 ＋ 事务接受”** 模型，不强制全域充血聚合根或机械的 `Command → Facts → Plan` 空壳包装链：

| 责任层 | 输入与产出 | 硬边界 |
| --- | --- | --- |
| **纯核心（Pure Core）** | 显式类型化输入 → 决策结果、派生结构或纯领域错误 | 同步、确定性、零 I/O；不读数据库、文件、网络、环境变量、系统时钟或随机源；不代表状态已持久化 |
| **写用例（Command）** | 当前状态、调用方身份与操作意图 → 已提交结果／收据 | 装载前态、按固定锁序加锁、调用纯核心、锁内重验资格并唯一提交 |
| **只读查询（Query）** | 筛选条件与已提交记录 → 只读视图／DTO | 不调用写状态机，不执行 DML 或排他锁 |
| **运行宿主（Server / Worker / CLI）** | 外部协议请求或调度信号 → 调用公开用例 | 负责进程生命周期、参数解包、连接／租约管理与协议错误映射，不内嵌业务规则或直接操作业务表 |

- **代码载体红线**：二进制组合根与协议适配层禁止内嵌业务 SQL 或直接开启／提交业务事务；私有存储辅助模块（`records.rs`／`store.rs`）只放模块内读写共用的锁、前态读取与私有 `Row`，禁止持有连接池或充当通用 `Repository` 对象壳；内存文档／导出编码器（`output/`）只消费纯语义模型输出字节流，禁止反向执行 I/O。

### 1.3 软件工程范式分工：轻量 DDD × 实用 DOD × 去 OOP 糟粕
在 Rust 中严禁照搬传统 OOP 对象图架构，而应按**语义控制面**与**批量数据面**正交组合范式：

- **对面向对象（OOP）取 2 弃 3**：
  - **保留** ① **单实例不变量封装**（私有字段＋受检构造＋维护局部守恒的方法）与 ② **外部边界窄多态**（仅在真实可替换传输／后端边界定义窄 Trait）。
  - **摒弃** ③ **类继承模拟**（滥用 `Deref`）、④ **跨实体可变对象指针网**（`Rc`／`Arc<Mutex<_>>` 双向互指图）与 ⑤ **无状态 `Service`／`Manager`／`Repository` 套壳对象**。
- **DDD 与 DOD 正交互补（“对外 DDD 契约，对内 DOD 布局”）**：DDD 决定**业务语义与事务一致性边界**，DOD 决定**内存物理布局与批处理吞吐**——淘汰的是“用 OOP 嵌套对象图实现战术 DDD”，而非领域边界本身：

| 维度 | 轻量 DDD（控制面，$O(1)$ 状态头） | 实用 DOD（数据面，$O(N)$ 同构事实集） |
| --- | --- | --- |
| **主导场景** | 限界上下文切分、权限与职责分离、单据／生命周期状态机、并发事务锁序、模块公开契约 | 多阶段核算／公式引擎（`engine/`）、树／图层级归集、结构化文档解析导出、批量 SQL 读写 |
| **Rust 落地载体** | 垂直模块切片、受检值对象（Newtype）、互斥状态 `enum`、最小聚合状态头校验 | 连续 `Vec<T>`、**紧凑整数／排序序号索引**（替代指针树）、**切片批变换** `fn(&[In]) -> Vec<Out>`、冷热字段分离、SQL `ANY`/`UNNEST` 列数组 |
| **越界禁令** | **严禁将上万条明细建成内存父子对象树**逐个调方法或循环 `.save()` | **严禁将裸 `usize` 下标或拆碎的平行列数组（SoA）泄漏至模块公开 API** 或低频业务状态机 |

```rust
// Good (DOD 内核): 用连续数组 + 紧凑整数句柄表达层级树，零指针跳转、零生命周期纠缠
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub(crate) struct NodeOrd(u32);

pub(crate) struct HierarchyArena<K> {
    keys: Vec<K>,
    parent: Vec<Option<NodeOrd>>, // 与 keys 按同一序号对齐的紧凑父指针
}
```

## 2. 目录形态、单向依赖与导入纪律

### 2.1 模块组织与薄 `mod.rs` 门面
1. **按职责内聚选型**：单一内聚能力默认采用单个具名 `.rs` 文件（常见舒适阅读区间约 `200–800` 行，作为认知信号而非机械行数截断）；模型、写命令与多维读查询确有独立演进复杂度时，拆分为 `capability/{mod.rs, model.rs, commands.rs, queries.rs}`（或多动作子目录 `commands/`、`queries/`、`engine/`）。生产 `src/` 避免使用语义含糊的 `core.rs`、`utils.rs`、`helpers.rs`、`common.rs` 杂物袋。
2. **薄 `mod.rs` 与真实路径挂载**：多文件目录统一采用 `<capability>/mod.rs` 入口，**禁止同级并存 `foo.rs` + `foo/`**，**禁止在 `mod.rs` 使用 `*` 通配重导出**。`mod.rs` 仅声明子模块并具名导出公开契约，不承载 SQL 或事务编排，也不充当兄弟子模块间的私有中转站（兄弟模块直接 `super::<sibling>::Item` 引用）。**严禁使用 `#[path = "..."]` 跨目录挂载源码**（单测拆文件统一用同目录 `#[cfg(test)] mod tests;`）。
3. **单向依赖硬红线**：写命令与只读查询确需共用私有行解码或前态装载时，下沉至模块私有的 `records.rs`／`store.rs`，**严禁写命令反向依赖 `queries` 模块**；仅单处使用的专属 SQL 就近留在对应命令或查询函数内。

```text
协议适配（HTTP / RPC / CLI）／Worker  ──▶  领域模块公开用例
写命令（commands）                    ──▶  纯模型／纯算子 ＋ 专属 DML／私有 store ＋ 同事务协作入口
只读查询（queries）                   ──▶  私有 Row 投影 ＋ 纯派生函数（严禁反向调用 commands）
私有存储辅助（records / store）       ──▶  纯类型的受检构造／恢复入口
```

### 2.2 导入（`use`）三段分组纪律
1. 文件顶部 `use` 按三段分组并以空行分隔：**① `std` / `core` / `alloc` → ② 第三方与工作区其他 crate → ③ 本 crate 内部模块（`crate::` / `super::` / `self::`）**。
2. 生产代码保持单层扁平具名导入，**禁止把整个 `crate::{...}` 合并成多层深缩进树**，**禁止非枚举变体的 `*` 通配导入**（测试模块允许 `use super::*;`）。跨模块自由函数优先保留父模块前缀调用（如 `codec::encode(...)`）以显露职责来源。

## 3. 工程角色命名、存储恢复边界与内部 API 克制

### 3.1 工程角色后缀与函数成本前缀
遵循 Rust 标准大小写（`UpperCamelCase` / `snake_case` / `SCREAMING_SNAKE_CASE`），按真实工程职责统一后缀：

| 类型角色 | 标准后缀或形式 | 边界约束 |
| --- | --- | --- |
| 领域实体／值类型 | 领域名词（`LedgerEntry`） | 避免空泛的 `Data`、`Info`、`Model`、`Object` |
| 强类型身份／确切引用 | `Id` / `Ref` | `Id` 标识身份，`Ref` 绑定身份＋确切版本或摘要 |
| 命令输入／提交回执 | `Command` / `Input` / `Receipt` | **`Receipt` 仅用于已持久化提交的回执**，严禁命名未落库候选 |
| 查询条件／只读投影 | `Filter` / `View` / `Entry` / `Page` | 类型名已清晰时不再叠加冗余 `View`/`Output` |
| 模块私有数据库行 | `Row` | 严格封闭在模块内部，严禁跨包导出或充当外部 API Schema |
| 协议请求／响应／错误 | `Request` / `Response` / `Query` / `Error` | 类型名不缩写为 `Req`/`Resp` |

- **函数命名与物理单位**：布尔判定用 `is_*`／`has_*`／`can_*`；只读访问器直接用名词（**不加 `get_` 前缀**）；转换方法严格按成本区分 `as_*`（$O(1)$ 借用视图）、`to_*`（编码或克隆构造新值）、`into_*`（消费 `self` 转移所有权）；既有修改又有校验的函数必须诚实命名为 `normalize_and_validate`。非强类型量纲字段必须带明确物理单位后缀（如 `timeout_ms`、`ttl_secs`、`max_bytes`）。

### 3.2 新建校验、历史记录恢复与证明令牌
- **新建输入 vs 历史记录恢复**：新建请求执行全部当前业务规则；从数据库恢复历史已定案记录时，严格核验结构完整性、已知枚举码、必填关联与摘要一致性，但**不得套用当前已演进的可变配置否定历史合法记录**。数据库出现未知枚举或完整性缺失时，必须归类为**服务端存储损坏错误**，严禁误报为客户端 400 错误或静默填充默认值。
- **证明令牌（Proof Token）禁克隆**：前置核验或鉴权签发的证明类型仅对当次输入有效，禁止为其派生 `Clone`／`Copy` 跨请求缓存复用以逃避终局事务锁内重验。
- **内聚上下文替代长参数列表**：禁止压制 `clippy::too_many_arguments` 透传七八个零散参数；将稳定共现的领域概念提炼为具名结构体或借用视图，禁止造无领域语义的一次性 `DoWorkArgs` 袋子。

### 3.3 非发布内部工作区 API 克制原则（`publish = false`）
- **拒绝面向对象套壳与过度防御**：默认使用具体类型与普通函数，坚决摒弃单实现 `IXxxService`／`XxxServiceImpl` 套壳；不为假设的未来扩展预写复杂泛型 Builder、密封 Trait（`Sealed`）或铺满 `#[non_exhaustive]`（避免破坏工作区内部枚举穷尽匹配保护）。
- **关键边界文档契约**：跨模块核心入口用 rustdoc 写明类型签名无法表达的前置不变量、锁序要求及 `# Errors`／`# Panics`／`# Safety`，文档示例统一使用 `?` 传播错误。
