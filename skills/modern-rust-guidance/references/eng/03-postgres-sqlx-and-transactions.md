# Eng 03 — PostgreSQL/SQLx 读写链路、唯一事务提交者与失败关闭

本分册定义基于 PostgreSQL 与运行时 SQLx 的无状态连接矩阵、模块私有 `FromRow`、批量防 N+1、两类标准写事务流水线、伴生审计／幂等失败关闭机制以及追加式迁移纪律。

## 1. 数据库边界与连接传递模型

### 1.1 运行时参数化 SQLx 与最小权限隔离
- **统一使用运行时参数化查询**：使用 `sqlx::query`、`query_as`、`query_scalar` 与显式 `.bind(...)` 绑定参数，避免引入重型 ORM 或使全仓离线编译强耦合实时数据库实例的编译期宏；严禁字符串拼接外部输入构造 SQL。
- **最小权限运行角色**：应用运行期连接固定明确 Schema `search_path`，使用无权执行 DDL、`TRUNCATE`、禁用触发器或篡改复制角色的受限数据库账号；Schema 迁移由独立维护流程执行。不同限界上下文的逻辑数据库各自维护迁移序列，严禁跨库 JOIN 或跨库隐式补偿替代单库强一致事务。

### 1.2 无状态函数与连接参数矩阵
模块内部通过无状态函数显式传递连接池或事务引用，**严禁构建长期持有 `PgPool` 的 `XxxRepository`／`XxxStore` 套壳对象**；`PgPool` 自身已是 `Arc` 句柄，**严禁再套 `Arc<PgPool>`**。

| 调用角色 | 标准连接参数 | 事务与快照责任 |
| --- | --- | --- |
| 对外写命令入口（唯一提交者） | `&PgPool` ＋ 已验证调用上下文 | 开启事务（或交由统一泛型事务执行器持有事务），绑定追踪／审计与语句超时上下文，串联全流程并**唯一执行 `tx.commit().await`** |
| 同事务跨模块写入协作方 | `&mut Transaction<'_, Postgres>` ＋ 前置证据 | 借用外层已开启事务执行本模块校验与写入，**严禁自行从池取新连接或调用 `commit`** |
| 共享快照只读核验 | `&mut PgConnection` | 复用调用方当前连接或事务解引用快照执行只读核验，不提交 |
| 独立只读查询 | `&PgPool` | 单语句直接走池读取；多表读取要求严格同一逻辑时点快照时，显式开启 `REPEATABLE READ READ ONLY` 只读事务 |

- **固定锁序防死锁**：同一事务需锁定多类资源或多行明细时，必须先按固定表层级与主键升序排序后再依次执行 `FOR UPDATE`／`FOR NO KEY UPDATE`，根除交叉加锁死锁；共享同一 `&mut Transaction` 或 `&mut PgConnection` 的数据库调用必须严格串行 `.await`。

## 2. 读链路：私有 `FromRow`、批量防 N+1 与边界准入

### 2.1 模块私有 `FromRow` 与纯同步解码
- 结构化查询使用模块私有的 `#[derive(sqlx::FromRow)]` 配合 `query_as`（单标量列用 `query_scalar`；仅检查存在性必须用 `SELECT EXISTS(...)`，禁止拉取整行或跑全表 `COUNT(*)`）。
- **`Row` 严格封闭在模块内部**：`Row` 只映射数据库物理列，严禁跨 crate 导出、直接充当领域实体或复用作外部 HTTP DTO。从 `Row` 到领域模型的 `TryFrom` 保持纯同步结构与值域核验，严禁夹带二次 I/O。

### 2.2 批量读写防 N+1 与大载荷并发配额
- **严禁循环内 `.await` 触发 N+1 查询**：集合读取必须使用 `WHERE id = ANY($1)` 或 `UNNEST` 批量拉取（超大集合按参数上限有界分块，任一分块失败必须整体报错，严禁返回残缺半截数据），再在内存中按键装配；空输入切片在发 SQL 前直接短路返回空集合。
- **批量明细写入与影响行数核验**：同事务多行同质写入优先用等长数组 `UNNEST(...)` 或受控分块 `QueryBuilder`；乐观锁与条件 `UPDATE`／`DELETE` 必须附带预期版本／状态谓词并**严格核对 `rows_affected()`**，行数不符立即报错回滚。
- **大载荷与阻塞准入护栏**：读取或解码大型 `BYTEA`／`JSONB` 前先校验声明行数与字节上限；**持有数据库连接或事务锁期间严禁阻塞排队等待并发配额**（配额满立即快速失败返回暂时过载）；客户端中途取消请求时，后台尚未退出的阻塞计算任务必须继续持有其并发许可直至真正结束，防止取消风暴击穿进程内存。

```rust
// Good: 空切片短路 + 单次 ANY($1) 参数化批量查询私有 Row
async fn load_items_by_ids(
    conn: &mut PgConnection,
    ids: &[Uuid],
) -> Result<Vec<ItemRow>, sqlx::Error> {
    if ids.is_empty() {
        return Ok(Vec::new());
    }
    sqlx::query_as::<_, ItemRow>("SELECT id, code, version FROM items WHERE id = ANY($1)")
        .bind(ids)
        .fetch_all(conn)
        .await
}
```

## 3. 两类写事务流水线、失败关闭与迁移护栏

### 3.1 短事务写命令与重型计算三阶段协议
1. **短事务写命令（6 步）**：① 锁外完成纯输入解析与规范化 → ② 开启事务并绑定追踪／审计上下文 → ③ 锁定幂等键比对请求摘要（同键同摘要直接重放原不可变收据；未命中则按锁序锁定前态、核验版本并执行纯规则裁决） → ④ 执行专属 DML → ⑤ 同事务写入审计记录与幂等收据 → ⑥ 唯一提交者提交。
2. **重型计算三阶段协议**：① **轻事务捕获与入队**（锁定并固化不可变输入版本与摘要，同事务落库作业记录、审计与幂等收据后立即提交返回受理回执） → ② **事务外纯计算**（后台执行者按已固化的确切引用装载输入并运行纯算子产出候选，严禁长时占用写事务，严禁偷读运行时刻的新数据） → ③ **终局短事务重验接受**（按锁序重锁可变状态头，复核权限、预期版本、输入未漂移且作业租约有效后，原子写入正式结果、血缘、审计与作业终态；任一前提漂移立即整笔回滚）。

### 3.2 数据库守卫正交、失败关闭（Fail-Closed）与追加迁移
- **数据库完整性 vs Rust 规则正交**：PostgreSQL 负责主键／外键／唯一／值域 `CHECK`／排他约束、并发锁仲裁、已封存记录不可变触发器与同事务物理写入标记（优先基于 `(system_identifier, xid8)` 而非易回绕的 32 位 `xmin`）；Rust 唯一拥有复杂状态机裁决、精确算子与规范散列。**严禁在 Rust 与 PL/pgSQL 触发器中双份重复编码同一业务分支**。
- **审计与幂等失败关闭**：凡要求留痕与幂等的写操作，业务状态写入、伴生审计落库与幂等收据登记必须在**同一物理事务**内完成（同幂等键若摘要不一致立即拒绝，重放则原样返回首次收据且不重复追加事件）；**任一环节失败必须无条件回滚整笔事务**。
- **不可变追加迁移**：DDL 变更仅以连续递增编号的 `.sql` 文件追加至所属模块的 `migrations/` 目录；热路径关联与血缘外键列同步建立前导索引；**严禁修改已合入主干的历史迁移文件或其校验和**。
