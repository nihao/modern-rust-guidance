# Lang 02 — 所有权、内存布局、集合选型与缓冲迭代

本分册定义函数所有权签名契约、借用检查冲突消解、类型内存布局与析构顺序、标准容器选型、零拷贝切片迭代以及缓冲 I/O 纪律。

## 1. 所有权签名与借用冲突消解（`own-*`）

### 1.1 参数与返回值所有权契约
- **只读参数最大化通用借用**：仅读取数据时，签名优先接收 `&str`（禁 `&String`）、`&[T]`（禁 `&Vec<T>`）、`&Path`（禁 `&PathBuf`）、`Option<&T>`（禁 `&Option<T>`）。
- **消费型参数诚实按值接收 `T`**：函数内部必定要长期持有或转交所有权时，直接声明 `value: T`，把移动或显式 `.clone()` 的决策权交给调用方；**严禁签名伪装成只读 `&T` 却在函数内部偷偷 `.clone()`**，也严禁对已是拥有型的值写 `.to_string().to_owned()` 或解引用 `.to_vec()` 造成双重分配。
- **条件性修改使用 `Cow`**：绝大多数输入原样借用返回、仅极少数转义／规范化分支需要新分配时，返回 `std::borrow::Cow<'a, str>` 或 `Cow<'a, [T]>`。
- **返回值与热缓冲复用**：多返回值优先用具名结构体；仅在热循环内反复编码填充时才由调用方传入预分配 `&mut Vec<u8>`／`&mut String` 并在每轮 `.clear()` 复用（保留底层 `capacity`）。

### 1.2 四步消解借用冲突（拒绝盲目 `.clone()`）
为绕过借用报错而随手 `.clone()` 既浪费堆分配，又可能使后续状态变更落在临时副本上静默丢失。按以下优先级消解：
1. **收窄借用跨度**：先拷出所需的 `Copy` 标量（如长度、ID、偏移），或用局部作用域 `{ ... }` 提前结束不可变借用，再发起可变借用。
2. **零拷贝原地置换**：从 `&mut self` 或可变枚举变体移出拥有型字段时，使用 `std::mem::take`、`std::mem::replace` 或 `Option::take`，同时确保置换后的原实例仍满足类型不变量。
3. **不相交字段借用拆分（Split Borrows）**：编译器支持同时借用 `&mut self.buf` 与 `&self.cfg`，但 `self.step()` 会锁死整个 `self`。将内部辅助函数改为精确接收字段 `step(&mut self.buf, &self.cfg)`，或将正交状态拆分为独立子结构体。
4. **共享不可变所有权显式指针克隆**：跨线程／跨任务共享只读大数据用 `Arc<T>`（或不可变切片 `Arc<[T]>`／`Arc<str>` 省去双层间接寻址与多余容量字），克隆时统一写 `Arc::clone(&shared)` 标明 $O(1)$ 原子计数递增；读多写少快照更新可配合 `Arc::make_mut` 实现写时复制。

## 2. 内存布局、枚举瘦身与析构顺序（`mem-*`）

### 2.1 空位（Niche）优化与大枚举变体 `Box` 瘦身
- **利用 Niche 消除判别式开销**：引用 `&T`、`Box<T>`、`NonNull<T>` 及 `NonZeroU32`／`NonZeroUsize` 均含非法零值空位，使得 `Option<NonZeroUsize>` 与 `usize` 等宽零额外字节。正数限额、页大小、并发度与非零标识优先使用 `NonZero*`。
- **抑制高频枚举／`Result` 最大变体膨胀**：`enum` 的栈体积由**最大变体**决定。当高频返回的小类型 `Result<SmallVal, RichError>` 或核心状态枚举中混有罕见大载荷变体（如完整诊断上下文或巨型子语法树，体积相差数倍以上）时，**必须将该罕见大变体包裹为 `Box<LargePayload>`**，避免每次正常返回都在栈上搬移数百字节：

```rust
// Good: 将罕见的大体积诊断载荷装箱，保持热路径 Result 栈帧紧凑
pub enum EvalError {
    DivisionByZero,
    Overflow,
    Diagnostic(Box<DetailedDiagnostic>),
}

const _: () = assert!(std::mem::size_of::<EvalError>() <= 16);
```

### 2.2 确定性析构顺序（Drop Order）与防循环引用
- **牢记两套相反的析构顺序**：
  1. **函数局部变量**按声明的**逆序（后进先出）**析构。
  2. **结构体与枚举变体的字段**按源码声明的**正序（从上到下）**析构——若字段 A（如内存映射视图、游标句柄）在析构时依赖字段 B（底层文件或竞技场分配器）仍然存活，**必须将依赖方字段 A 声明在被依赖字段 B 之前**，并附注释说明顺序不变量。
- **显式提前释放与防泄漏**：需在作用域结束前主动归还锁或大块内存时，调用具名 `drop(guard)`；使用引用计数构建双向图结构时必须用 `Weak<T>` 打断回边，严禁 `Arc`/`Rc` 闭环导致内存永久泄漏。

## 3. 集合选型、切片迭代与缓冲 I/O（`coll-*` / `perf-*`）

### 3.1 容器选型、确定性键序与单次查找（`Entry` API）
- **单次探测更新强制用 `Entry` API**：按键插入、累加或初始化时使用 `map.entry(key).and_modify(...).or_insert_with(...)`，**严禁先 `contains_key`／`get` 再 `insert` 造成双倍比较或哈希计算**。
- **按真实访问复杂度选容器**：
  - 默认顺序存储与紧凑缓存局部性首选 `Vec<T>`。
  - 双端队列与头部弹出必须用 `VecDeque<T>`（**严禁在循环中调用 `Vec::remove(0)` 造成 $O(n^2)$ 搬移**；禁止在通用代码中选用指针追逐严重的 `LinkedList`）。
  - Top-K 或优先级调度使用 `BinaryHeap<T>`（最小堆包裹 `std::cmp::Reverse`）。
- **可观察输出强制确定性顺序**：凡影响持久化字节、散列摘要、分页结果、导出报表或快照比对的键值集合，**严禁依赖 `HashMap`／`HashSet` 的随机化种子遍历顺序**，必须使用 `BTreeMap`／`BTreeSet` 或在输出前显式稳定排序（`sort_by`／`sort_by_key`）。

### 3.2 切片迭代器、受检预分配与缓冲流 I/O
- **迭代器消除边界检查**：遍历连续内存优先用 `.iter()`、`.iter_mut()`、`.chunks(n)`、`.windows(n)` 或 `.split_at(mid)`，替代手写 `for i in 0..v.len() { v[i] }`（既防越界 panic，又利于编译器向量化）。
- **上限校验后再 `with_capacity`**：已知合法元素数量时用 `Vec::with_capacity(n)` 消除扩容拷贝，但**严禁直接将未经上限核验的外部输入长度传给 `with_capacity` 引发 OOM**。
- **消除无意义中间 `collect`**：纯映射过滤链保持惰性串联；状态转移复杂或含多路提前跳出时，直接写清晰的 `for` 循环优于生硬嵌套组合子。
- **文件与流读写强制缓冲**：对 `std::fs::File` 或字节流执行多次小块读写／按行扫描时，**必须包裹 `std::io::BufReader`／`BufWriter`**（写入结束显式 `.flush()?` 检查落盘错误），严禁裸流逐次触发系统调用。
